# Первые шаги

:::info[Оригинал]
[docs.nestjs.com — First steps](https://docs.nestjs.com/first-steps) · NestJS 12.1 · перевод от 01.10.2026
:::

В этой серии статей разбираются **основы** Nest. Чтобы познакомиться с ключевыми строительными блоками Nest-приложения, мы напишем простое CRUD-приложение, возможности которого охватывают многие темы на начальном уровне.

## Язык {/* #language */}

Nest написан на [TypeScript](https://www.typescriptlang.org/), работает на [Node.js](https://nodejs.org/en/) и поддерживает как TypeScript, так и чистый JavaScript. Поскольку Nest опирается на новейшие возможности языка, для работы с ним на чистом JavaScript понадобится [Babel](https://babeljs.io/).

Большинство примеров в этой документации написаны на TypeScript, но **любой фрагмент кода** можно переключить на синтаксис чистого JavaScript с помощью переключателя языка в правом верхнем углу фрагмента.

:::note[Примечание]
В этом конспекте переключателя нет: все примеры кода приводятся только на TypeScript.
:::

## Требования {/* #prerequisites */}

Убедитесь, что в вашей операционной системе установлен [Node.js](https://nodejs.org). Для запуска Nest-приложения нужна версия **v20.19 или новее** (или **v22.12+** в линейке 22.x). Генераторам Nest CLI (например, `nest new` и `nest generate`) нужна версия **v22.22.3+, v24.15+ или v26+**. Мы рекомендуем последний активный LTS-релиз — он удовлетворяет обоим требованиям.

## Настройка {/* #setup */}

Быстрее всего создать новый проект с помощью Nest CLI{/* TODO-LINK: https://docs.nestjs.com/cli/overview — CLI → Overview */}. Если у вас установлен [npm](https://www.npmjs.com/), выполните в терминале следующие команды:

```bash
$ npm i -g @nestjs/cli
$ nest new project-name
```

CLI спросит, какую систему модулей использовать: ESM (по умолчанию) с Vitest в качестве тест-раннера или CommonJS с Jest.

Также CLI спросит, нужно ли подключить [NestJS Observe](https://www.observe.nestjs.com/) — официальную платформу observability (наблюдаемости) для Nest. Если ответить «да», в сгенерированный проект будет добавлен SDK `@nestjs/observe`, уже подключённый в `AppModule` и `NestFactory.create()`. Запросы, фоновые задачи, ошибки и распределённые трейсы начнут отправляться, как только вы укажете ключ и секрет приложения; для бесплатного тарифа платёжные данные не нужны. В интерактивном терминале по умолчанию предлагается «да»; в неинтерактивных окружениях, например в CI, вопрос пропускается и Observe не добавляется. Чтобы пропустить вопрос, передайте `--observe` или `--no-observe`. О возможностях Observe — в главе «Observability»{/* TODO-LINK: https://docs.nestjs.com/observability/overview — Observability → Overview */}.

:::tip[Подсказка]
Новые проекты генерируются с включённым [strict](https://www.typescriptlang.org/tsconfig#strict)-режимом TypeScript. Чтобы отключить его, укажите `"strict": false` в сгенерированном `tsconfig.json`.
:::

CLI создаст директорию `project-name`, установит зависимости, сгенерирует несколько шаблонных файлов и наполнит директорию `src/` несколькими основными файлами.

```text
src
├── app.controller.spec.ts
├── app.controller.ts
├── app.module.ts
├── app.service.ts
└── main.ts
```

Назначение этих основных файлов:

| Файл                     | Описание                                                                                          |
| ------------------------ | ------------------------------------------------------------------------------------------------- |
| `app.controller.ts`      | Простой контроллер с одним маршрутом.                                                             |
| `app.controller.spec.ts` | Модульные тесты для контроллера.                                                                  |
| `app.module.ts`          | Корневой модуль приложения.                                                                       |
| `app.service.ts`         | Простой сервис с одним методом.                                                                   |
| `main.ts`                | Точка входа приложения. Использует `NestFactory` для создания экземпляра Nest-приложения.         |

Файл `main.ts` содержит асинхронную функцию, которая **запускает** (bootstrap) приложение:

```ts title="main.ts"
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module.js';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  await app.listen(process.env.PORT ?? 3000);
}
await bootstrap();
```

Чтобы создать экземпляр Nest-приложения, используется класс `NestFactory` из `@nestjs/core`, у которого есть несколько методов для этого. Метод `create()` возвращает объект приложения, реализующий интерфейс `INestApplication`. Методы этого объекта описаны в следующих главах. В примере `main.ts` выше приложение запускает HTTP-слушатель и ожидает входящие HTTP-запросы.

Структура проекта, которую генерирует Nest CLI, поощряет соглашение хранить каждый модуль в отдельной директории.

:::tip[Подсказка]
По умолчанию, если при создании приложения происходит ошибка, процесс завершается с кодом `1`. Чтобы вместо этого ошибка выбрасывалась, отключите опцию `abortOnError` (например, `NestFactory.create(AppModule, { abortOnError: false })`).
:::

## Платформа {/* #platform */}

Nest спроектирован так, чтобы не зависеть от платформы. Независимость от платформы позволяет создавать переиспользуемые логические части, которые можно применять в приложениях разных типов. Nest может работать с любым HTTP-фреймворком для Node.js, если для него написан адаптер. Из коробки поддерживаются две HTTP-платформы: [Express](https://expressjs.com/) и [Fastify](https://www.fastify.io). Выберите ту, что лучше подходит под ваши задачи.

| Пакет              | Описание                                                                                                                                                                                                                                                   |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `platform-express` | [Express](https://expressjs.com/) — известный минималистичный веб-фреймворк для Node.js. Это проверенная временем, готовая к продакшену библиотека с большим количеством материалов от сообщества. По умолчанию Nest использует пакет `@nestjs/platform-express`, поэтому никакой настройки не требуется. |
| `platform-fastify` | [Fastify](https://www.fastify.io/) — высокопроизводительный фреймворк с низкими накладными расходами, ориентированный на эффективность и скорость. Как его использовать — в главе «Производительность (Fastify)»{/* TODO-LINK: https://docs.nestjs.com/http/performance — HTTP → Performance (Fastify) */}. |

У каждой платформы свой интерфейс приложения: `NestExpressApplication` и `NestFastifyApplication` соответственно.

Если передать тип в метод `NestFactory.create()`, как в примере ниже, у объекта `app` появятся методы, доступные только на этой платформе. Указывать тип **не обязательно**, **если только** вам не нужен доступ к API нижележащей платформы.

```ts
const app = await NestFactory.create<NestExpressApplication>(AppModule);
```

## Запуск приложения {/* #running-the-application */}

После завершения установки выполните следующую команду, чтобы запустить приложение и начать принимать входящие HTTP-запросы:

```bash
$ npm run start
```

:::tip[Подсказка]
Чтобы ускорить сборку при разработке, используйте SWC-сборщик{/* TODO-LINK: https://docs.nestjs.com/recipes/swc — Recipes → SWC (fast compiler) */}, передав флаг `-b swc` скрипту `start`: `npm run start -- -b swc`.
:::

Эта команда запускает HTTP-сервер на порту, указанном в файле `src/main.ts` (`3000`, если не задана переменная окружения `PORT`). Когда приложение запустится, откройте браузер и перейдите по адресу `http://localhost:3000/`. Вы должны увидеть сообщение `Hello World!`.

Чтобы отслеживать изменения в файлах, запускайте приложение такой командой:

```bash
$ npm run start:dev
```

Эта команда следит за файлами и при каждом изменении перекомпилирует и перезапускает сервер.

## Линтинг и форматирование {/* #linting-and-formatting */}

Nest CLI{/* TODO-LINK: https://docs.nestjs.com/cli/overview — CLI → Overview */} стремится сразу задать надёжный и масштабируемый процесс разработки. Для быстрого старта в сгенерированных TypeScript-проектах заранее установлены **линтер** и **форматтер** кода: [oxlint](https://oxc.rs/docs/guide/usage/linter.html) и [Prettier](https://prettier.io/) соответственно.

:::tip[Подсказка]
Не уверены, чем форматтеры отличаются от линтеров? Посмотрите [сравнение](https://prettier.io/docs/en/comparison.html) в документации Prettier (на английском).
:::

Для окружений без IDE (непрерывная интеграция, Git-хуки и т. п.) в проекте есть готовые `npm`-скрипты, которые запускают [`oxlint`](https://www.npmjs.com/package/oxlint) и [`prettier`](https://www.npmjs.com/package/prettier):

```bash
# Линтинг с помощью oxlint
$ npm run lint

# Форматирование с помощью prettier
$ npm run format
```
